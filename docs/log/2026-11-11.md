### Found / learned
- **QMK start-up order (QMK `master`, read from source):** `keyboard_init()` calls `backlight_init_ports()`
  (`quantum/keyboard.c:483`) before `backlight_init()` (`:510`), which loads the saved settings. The ChibiOS PWM
  driver checks `is_backlight_breathing()` inside `backlight_init_ports()` (`platforms/chibios/drivers/backlight_pwm.c`),
  so a saved "breathing on" never starts the breathing timer at power-up. `backlight_enable_breathing()` can't be used
  to fix it, since it returns early when the saved flag is already set (`quantum/backlight/backlight.c`). Workaround:
  call `breathing_enable()` (public, `backlight.h`) from `keyboard_post_init_user()`.
- Claude said the first PWM build would breathe without checking that start-up order: a clean build doesn't show
  behaviour. Only the owner's test caught it.
- `#include_next` order: `halconf.h` defines **before** the include (QMK's base file only fills in undefined values);
  `mcuconf.h` includes **first**, then `#undef`/`#define` (the base file sets every value).
- The clone's flash works with QMK's default second-stage bootloader; no `RP2040_FLASH_*` define needed.
- RP2040-Zero edge pins have one GND (left side, second from top, footprint pad 22); breadboard grounds go via the rail.
- **Correction to [log 2026-11-04 Session 2](2026-11-04.md):** the owner's "now on dev" most likely meant this repo's `dev` branch,
  not QMK's `develop`. QMK's branch is `master` (above).
- 220 Ω may give more brightness than needed. The resistor sets the maximum and PWM dims below it, so pick R3–R6 under
  a real switch at full duty.
